## 1. High-Level Architecture

CodePilot is an **Electron + Next.js** desktop application that wraps Claude Code's Agent SDK into a full-featured GUI. It combines real-time streaming AI, multi-provider support, MCP server management, and remote control via instant messaging platforms.

![CodePilot High-Level Architecture](draw:021b16)

### Tech Stack Summary

| Layer | Technology | Purpose |
|-------|-----------|---------|
| Desktop Shell | Electron 40.x | Cross-platform window management |
| Frontend | Next.js 16 (App Router) + React 19 | UI rendering + API routes |
| Styling | Tailwind CSS 4 + Radix UI | Component library |
| Database | better-sqlite3 (WAL) | All-local persistence |
| AI Core | Claude Agent SDK | Tool use, streaming, permissions |
| AI Providers | @ai-sdk/* (Anthropic, Google, Bedrock, Vertex, OpenAI) | Multi-vendor support |
| IM Bridge | Telegram, Feishu, Discord, QQ | Remote control |
| Build | electron-builder | DMG/NSIS/AppImage packaging |

## 3. SSE Streaming Architecture

The streaming system is the heart of CodePilot — it decouples the SSE event stream from React component lifecycle using a `globalThis` singleton.

![SSE Streaming Architecture](draw:fd66df)

### How it works

1. **User sends message** → `POST /api/chat/messages`
2. **API route** creates Claude Agent SDK session via `claude-client.ts`
3. **SDK returns SSE stream** (`text/event-stream`)
4. **StreamSessionManager** (singleton on `globalThis`) consumes events, accumulates state
5. **Subscribers** (React hooks, Bridge engine, Permission broker) receive snapshot updates
6. **ChatView re-renders** with immutable snapshot objects (efficient React diffing)

### Why globalThis?

When a user switches chat tabs, the React component unmounts — but the stream keeps running. The singleton pattern ensures:
- Streams survive component unmount/remount
- Survives Next.js HMR in development
- Multiple consumers can subscribe independently

### Key data structure

```typescript
interface SessionStreamSnapshot {
  sessionId: string;
  accumulated_text: string;
  events: StreamEvent[];
  current_tool?: ToolUseInfo;
  rewind_points: RewindPoint[];
}
```

## 4. Provider System

CodePilot supports **multiple AI providers** through a catalog + resolver architecture.

![Provider Resolution & Multi-Provider System](draw:d1543c)

### Components

| Module | Lines | Role |
|--------|-------|------|
| `provider-catalog.ts` | 606 | Vendor presets (Anthropic, OpenRouter, Bedrock, Vertex, Google, custom) |
| `provider-resolver.ts` | 649 | Resolve provider → SDK env vars |
| `provider-doctor.ts` | 1,029 | Diagnostics with 5 probe types + auto-repair |

### Provider preset structure

Each provider defines:
- **Wire protocol** — `anthropic`, `openai-compatible`, `bedrock`, `vertex`
- **Auth style** — API key, env-only (IAM), custom header
- **Default env overrides** — injected into Claude Agent SDK
- **Model roles** — default, reasoning, small, haiku, sonnet, opus

### Fallback chain

1. Session-specific provider (user selected per chat)
2. Active provider (user-set default)
3. Global default model setting
4. Anthropic via CLI auth (hardcoded fallback)

## 5. Bridge — IM Remote Control

The Bridge system lets users control CodePilot from their phone via Telegram, Feishu, Discord, or QQ.

![Bridge IM Remote Control System](draw:ec17eb)

### Architecture layers

| Layer | File | Role |
|-------|------|------|
| **Adapters** | `adapters/*.ts` | Platform-specific polling/WS + message format |
| **Channel Router** | `channel-router.ts` | Maps IM message → CodePilot session |
| **Conversation Engine** | `conversation-engine.ts` | Consumes SSE stream, persists messages |
| **Permission Broker** | `permission-broker.ts` | Tool approval via IM inline buttons |
| **Delivery Layer** | `delivery-layer.ts` | Message splitting + rate limiting |
| **Markdown Render** | `markdown/*.ts` | IR → platform format (HTML/cards/markdown) |

### Permission flow (unique feature)

When Claude needs to execute a tool (write file, run command):
1. SDK emits `PermissionRequestEvent`
2. Permission Broker converts to IM inline buttons (Approve/Deny)
3. User taps button on their phone
4. Broker notifies SDK → execution continues or aborts

## 7. Database Schema

SQLite with WAL mode, **16 tables**:

### Core tables

```
chat_sessions    — Session metadata (title, model, provider, status)
messages         — Content as JSON array, token usage tracking
settings         — Key-value app settings
tasks            — SDK TodoWrite task items
api_providers    — User-configured providers
```

### Media tables

```
media_generations  — Generated images
media_tags         — Reusable labels
media_jobs         — Batch generation jobs
media_job_items    — Items within batch
media_context_events — Batch context snapshots
```

### Bridge tables

```
channel_bindings        — IM channel → session mapping
channel_offsets         — Polling watermarks
channel_dedupe          — Message dedup (7-day TTL)
channel_outbound_refs   — Sent message tracking
channel_audit_logs      — Audit trail
channel_permission_links — Permission → IM message links
```

### Migration strategy

- Runs at startup via `migrateDb()`
- Adds missing columns incrementally
- Foreign keys with CASCADE deletes

## 8. State Management

**No Redux or Zustand** — CodePilot uses a lightweight pattern:

| Pattern | Where | Purpose |
|---------|-------|---------|
| `useState` | Components | Local UI state |
| Custom hooks | `hooks/` | API call lifecycle |
| Context API | Theme, i18n, Settings | Global read-only state |
| `globalThis` singletons | Stream manager, conversation registry | Cross-component persistence |
| SSE subscription | `useSSEStream` | Real-time stream → React |

### Singleton pattern

```typescript
const KEY = '__streamSessionManager__';
globalThis[KEY] = globalThis[KEY] || createManager();
```

Survives HMR, component unmount, and page navigation.

## 10. Build & Deploy

### Development

```bash
npm run dev              # Next.js dev (localhost:3000)
npm run electron:dev     # Full Electron app
```

### Production build pipeline

1. Next.js builds to `output: 'standalone'`
2. `build-electron.mjs` copies standalone → dist-electron
3. electron-builder packages with resources
4. `after-pack.js` recompiles better-sqlite3 for Electron ABI
5. `after-sign.js` handles macOS codesigning

### Distribution

- **macOS:** DMG (arm64 + x64)
- **Windows:** NSIS installer (x64 + arm64)
- **Linux:** AppImage / deb / rpm
- **Updates:** electron-updater with differential downloads
