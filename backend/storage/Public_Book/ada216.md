## Security

### SSH Key Management Approach

- SSH keys are registered in **Workspace variables** for general use with minimal area separation for basic security
- Deployment keys are managed in **Bitbucket Secure Variables**, keys are not stored separately on runners
- Separating SSH keys per service would improve security but require more management resources
  - Service-specific example: `SSH_KEY_PROD_ServiceName`

| Variable Name | Description |
|--------------|-------------|
| SSH_KEY_DEV | Full private key for dev server |
| SSH_KEY_STAGE | Full private key for stage server |
| SSH_KEY_PROD | Full private key for prod server |

### 3. Use Runner Labels to Distinguish Target Runners (specify labels in bitbucket-pipeline.yml)

```yaml

  # Modify according to labels shown in Workspace Runner
  - self.hosted
  - linux.shell
  - tna
  - runner.test
```

### 4. Pipeline Example

```yaml
pipelines:
  default:
    - step:
        name: example
        runs-on:
          # Modify according to labels shown in Workspace Runner
          - self.hosted
          - linux
          - tna
          - docker
        script:
          - mkdir -p ~/.ssh

          # Save SSH_PRIVATE_KEY content to file
          - echo "$SSH_USER_DEV"
          - echo "$SSH_KEY_DEV" | base64 -d > ~/.ssh/id_rsa_dev
          - chmod 600 ~/.ssh/id_rsa_dev
          - ls -al ~/.ssh/id_rsa_dev
          - cat ~/.ssh/id_rsa_dev

          # Register known_hosts (Host key verification error occurs if missing)
          - ssh-keyscan -H 172.16.103.55 >> ~/.ssh/known_hosts;

          # Connect via SSH using -i option
          - ssh -o BatchMode=yes -i ~/.ssh/id_rsa_dev "${SSH_USER_DEV}@172.16.103.55" "ls -al /"
```

### Haproxy Commands

#### Remove Service (Drain then check processing sessions until scur=0)

```bash
[tomcat@DEV-HOT-Haproxy:/home/tomcat]$ sudo /usr/local/bin/haproxy_drain

[INFO] Setting be_dev_tna_all/DEV-tourvis-develop to DRAIN...
[INFO] Current state: DRAIN
[INFO] Waiting for sessions to drain (scur -> 0)...

[INFO] be_dev_tna_all/DEV-tourvis-develop drained (scur=0).
```

